## 环节 ①:程序要做判断,先学会"比大小"(10 min)

### 从一个麻烦说起

第 1 课的温度转换器会**算**了,但不会**看**:输入 38.6,它只会冷静地打印 `101.5°F`,不会提醒你"好像发烧了"。因为第 1 课的程序从头到尾只有一条路——不管数据是什么,执行的都是同一行 `print`。

想让它"看数据说话",第一步:先拿到一个**真假值**。

```python
print(38.6 > 37.3)   # True
print(38.6 < 37.3)   # False
print(37.3 >= 37.3)  # True
print(18 == 18)      # True
print(18 != 19)      # True
```

> 📘 **概念卡 · 比较运算符与 bool**
>
> **是什么**:`>` `<` `>=` `<=` `==`(等于)`!=`(不等于)用来比较两个值,**结果只有两种**:`True` 或 `False`——还记得第 1 课类型表里预告的"第 2 课的主角" bool 吗?就是它。
>
> **为什么需要**:判断需要依据。"发烧了吗"的依据是 `temp > 37.2`,这个式子算出的 `True/False` 就是程序走哪条路的开关。
>
> **特性**:
> - `==` 是**比较**(问一句"相等吗"),`=` 是**赋值**(把值存进变量),完全是两回事
> - `18 == 18` 是 `True`,但 `"18" == 18` 是 `False`——类型不同直接判"不等"("两个世界"铁律依然生效)

**故意写错**(新手 100% 会犯):

```python
print(18 = 18)    # ❌ SyntaxError
```

Python 的报错甚至直接给了建议:`Maybe you meant '==' instead of '='?`——记住:**`=` 存东西,`==` 比东西**。

**动手试**(先在心里猜答案,再运行验证):

```python
print(7 > 3)
print(7 < 3)
print(10 >= 10)
print("18" == 18)
```

## 环节 ②:if——让程序走岔路(15 min)

有了真假值,`if` 就能让程序**分情况做事**:

```python
temp = float(input("请输入体温:"))

if temp >= 37.3:
    print("⚠️ 发烧了,多喝水多休息")
else:
    print("体温正常")
```

要分三档?中间加 `elif`:

```python
if temp < 36.0:
    print("体温偏低")
elif temp <= 37.2:
    print("体温正常")
else:
    print("⚠️ 发烧了,多喝水多休息")
```

> 📘 **概念卡 · if 分支**
>
> **是什么**:`if 条件:` 条件为 `True` 就执行**缩进块**;不满足就看 `elif`,再不行走 `else`。
>
> **为什么需要**:现实里全是"分情况":密码对/错、猜的数大了/小了、成绩及格/不及格。只会顺序执行的程序,连体温都提醒不了。
>
> **特性**:
> - **冒号 + 缩进是语法的一部分**,不是图好看;缩进的行都属于这个分支
> - `elif` 可以有多个,`else` 最多一个且可省略
> - 从上到下**只走第一条成立的分支**,后面不再看(所以 37.0 会命中 `elif temp <= 37.2` 的"正常")

**现场演示三大新手错误**:

```python
if temp >= 37.3        # ❌ 行尾忘了冒号 → SyntaxError
    print("发烧了")

if temp >= 37.3:
print("发烧了")        # ❌ 冒号下一行没缩进 → IndentationError(第 1 课速查表见过它)

if temp = 37.3:        # ❌ 又把 == 写成 = → SyntaxError
    print("发烧了")
```

**动手试(成绩评价器)**:输入分数,`≥ 90` 打印"优秀",`≥ 60` 打印"及格",否则打印"不及格"。三种结果都要能测到——想想分别输入什么数字?

## 环节 ③:while——让程序重复干活(15 min)

### 从一个麻烦说起

现在程序会判断了,先写个"一次性"猜数字:

```python
answer = 50
guess = int(input("猜个 1~100 的数字:"))

if guess > answer:
    print("猜大了")
elif guess < answer:
    print("猜小了")
else:
    print("猜对了!")
```

问题来了:猜错一次,程序直接结束,想再猜得重新运行——**太不耐玩了**。我们需要让它"猜对为止"地**重复**一段代码:

```python
count = 1
while count <= 5:
    print(f"第 {count} 遍:好好学习")
    count += 1          # count = count + 1 的缩写
```

> 📘 **概念卡 · while 循环**
>
> **是什么**:`while 条件:` 只要条件为 `True`,就一遍遍执行缩进块;某次检查时条件变成 `False`,才停下来。
>
> **为什么需要**:重复的活不能靠复制粘贴代码——改一处忘三处。"猜到对为止""还有机会就继续问",天生就该循环。
>
> **特性**:循环三件套缺一不可——
>
> ```python
> count = 1            # ① 起点(初始化)
> while count <= 5:    # ② 终点(条件)
>     print(...)       #    干活
>     count += 1       # ③ 往前走(更新)
> ```

**故意写错(重点!)**——删掉第 ③ 步:

```python
count = 1
while count <= 5:
    print(f"第 {count} 遍:好好学习")   # count 永远是 1 → 条件永远成立
```

刷屏了!这就是**死循环**。救场快捷键:终端里按 **`Ctrl + C`** 强行终止程序。

> 死循环不丢人,每个程序员都写过;怕的是不知道 Ctrl + C。

**动手试(倒计时)**:打印 5、4、3、2、1,最后打印"🚀 发射!"。提示:每圈 `count -= 1`。

## 环节 ④:for 与 range——数着数干活(10 min)

### 从一个麻烦说起

想打印 1~100 每个数,用 while 得写全"三件套"。如果**重复几次是已知的**,`for` 一行搞定:

```python
for i in range(5):
    print("我错了")     # 打印 5 遍

for i in range(1, 6):
    print(i)            # 1 2 3 4 5
```

> 📘 **概念卡 · for 与 range**
>
> **是什么**:`for 变量 in range(...)` 让变量依次取 range 里的每个值,每取一次执行一遍缩进块。`range` 是"一串数"的生成器:
>
> | 写法 | 产生的数 |
> | ---- | -------- |
> | `range(5)` | 0, 1, 2, 3, 4 |
> | `range(1, 6)` | 1, 2, 3, 4, 5 |
> | `range(1, 10, 2)` | 1, 3, 5, 7, 9(第三个数是步长) |
>
> **为什么需要**:次数已知的重复,`for` 比 `while` 省心——不用自己管计数器,**天生不会死循环**。
>
> **特性**:**含头不含尾**。`range(1, 10)` 到 9 为止,10 不算。

**故意写错**(编程界经典笑话来源——"差一错误"):

```python
for i in range(1, 10):
    print(i)     # 想打印 1~10,结果只到 9!
```

**板书:while 还是 for?**

| 场景 | 用谁 | 例子 |
| ---- | ---- | ---- |
| 重复几次**数得出来** | `for` | 打印 10 遍道歉、九九乘法表 |
| **到某事发生为止**,次数未知 | `while` | 猜到对为止、密码对为止 |

**动手试**:打印 1~100 中 7 的倍数(一行一个)。提示:`for` 管数数,`if i % 7 == 0` 管筛选——第 1 课的 `%` 派上用场了。

## 环节 ⑤:两件新装备——random 魔盒与 break(10 min)

猜数字要好玩,还差两样:电脑得**随机出题**,程序得**猜中就停**。

### 装备 1:random——让电脑随机想一个数

```python
import random                     # 借工具:从 Python 自带的 random 工具箱借机器

answer = random.randint(1, 100)   # 1~100 之间随机一个整数(含 1 和 100)
print(answer)                     # 每次运行结果都不同
```

> `import` 是"借工具",原理第 6 课(模块)揭晓。现在先当魔盒用:**每次运行吐一个不同的随机整数**。

### 装备 2:break——立刻跳出循环

```python
while True:
    cmd = input("随便说点什么(输 q 退出):")
    if cmd == "q":
        print("再见!")
        break
    print(f"你说了:{cmd}")
```

> 📘 **概念卡 · break**
>
> **是什么**:循环里执行到 `break`,**立刻终止整个循环**,跳到循环后面的代码。
>
> **为什么需要**:很多循环的退出时机在循环**中间**而不是开头——"猜中了就停""输 q 就退"。`while True`(条件永远真)+ 在合适的位置 `break`,写起来最直白。
>
> **特性**:只跳出**所在的那层**循环;写在循环外面会直接 `SyntaxError`。

**故意写错**——break 缩进错位:

```python
while True:
    cmd = input("随便说点什么(输 q 退出):")
    if cmd == "q":
        print("再见!")
    break        # ❌ 缩进到了 if 外面:第一圈还没等输入就退出了
```

缩进决定 `break` 属于谁——"缩进是语法"的第二次教育。

**动手试**:把这段"聊天程序"敲下来跑一遍;再故意把 `if` 里的 `break` 删掉,看看会发生什么(还记得 Ctrl + C 吗)。

**本课核心模型**(接着第 1 课的模型往下长):


**本课概念清单**(能脱稿讲出大意就算掌握):

- 比较:`==` 问"相等吗",`=` 是"存进去",写混直接 SyntaxError

- while:三件套"起点 → 条件 → 更新",忘了更新就是死循环(Ctrl + C 救场)
- for + range:次数已知用 for;含头不含尾,`range(1, 10)` 到 9 为止
- break:立刻跳出所在循环;`while True` + `break` = "到某事发生为止"
- `random.randint(1, 100)`:魔盒,原理第 6 课揭晓

## 附录:本课常见报错速查表

| 报错 / 现象 | 常见原因 | 解决 |
| ----------- | -------- | ---- |
| `SyntaxError` + 光标停在行尾 | `if` / `elif` / `while` / `for` 行尾忘了 `:` | 补冒号 |
| `IndentationError: expected an indented block` | 冒号下一行没有缩进 | 冒号后的代码块统一缩 4 个空格 |
| `SyntaxError` 报错里提到 `=` | 把比较 `==` 写成了赋值 `=` | 比较用两个等号 |
| `SyntaxError: 'break' outside loop` | `break` 没写在 while / for 的缩进块里 | 把 `break` 移进循环体内 |
| 刷屏停不下来(死循环) | while 条件永远为 `True` | `Ctrl + C` 终止;检查条件里的变量有没有被更新 |
| `TypeError: '>' not supported between 'str' and 'int'` | `input()` 的结果没转 `int` 就去比大小 | `guess = int(input(...))` |
| `ValueError: invalid literal for int()` | 猜数字时敲了字母 | 好好敲数字;兜底方案第 7 课学 |
